# 설계 B: 화이트박스 로그확률 감사 + 요인 통제 실험

## 0. 왜 설계 B인가 (설계 A의 약점 보완)

설계 A의 한계:
- Qwen 1.5B는 논문의 Llama 70B와 질적 격차가 큼 → "모델이 약해서 그런 것"이라는 반박에 취약
- T=0.8 반복 샘플링(600 calls)은 CPU에서 느리고, 분포 추정이 간접적
- 무페르소나 조건만으로는 "모델 prior"와 "디코딩(temperature 0)"을 분리할 수 없음

설계 B의 핵심 개선 3가지:
1. **로그확률 직접 측정** — 샘플링 대신 답 토큰의 확률을 1회 패스로 읽음 (비판 1을 더 싸고 정확하게)
2. **셔플 페르소나 통제** — 페르소나 내용의 인과적 역할을 분리 (비판 2의 결정타)
3. **주입 용량-반응** — 명시/은근/없음 3단계로 "넣어도 지워진다"를 정밀 테스트 (비판 3 강화)

## 1. 모델·데이터 (설계 A와 동일)
- Qwen2.5-1.5B-Instruct-Q4_K_M (llama.cpp, CPU)
- NPK 리비전 ada0f5b5, seed 42, 구조화 12필드
- 질문 4문항 (Q1 출생국가 / Q2 장애등록 / Q3 성적지향 / Q4 성별정체성)

## 2. 모듈 1 — 로그확률 감사 (비판 1: 온도와 분포)

**방법**: 각 페르소나×질문마다 T=0 1회 호출하되, 답 위치에서 토큰 "1","2","3"의
로그확률(logprob)을 직접 기록. llama.cpp의 completion API가 토큰 확률 반환.

**판정**:
- P(소수자 옵션) < 1e-6 → 진짜 0. T=0이 가린 것이 아님 → **비판 1 기각**
- P(소수자 옵션) ≈ 0.05~0.3 → T=0이 분포를 가린 것. 논문의 "0명"은 디코딩 아티팩트 → **비판 1 지지**
- 중간값이면 질적 판단 (질문별 편차 보고)

**비용**: 100명 × 4문항 = 400 calls (샘플링 불필요). 약 40분.

## 3. 모듈 2 — 셔플 페르소나 통제 (비판 2: 페르소나 vs prior)

**방법**: 12개 필드를 사람 간 무작위 셔플한 "가짜 페르소나" 생성
(예: A의 나이·직업 + B의 지역·학력 + C의 가족형태...). 인구학적 그럴듯함은
유지되나 특정 개인과의 연결은 끊김.

**조건**:
- B0: 페르소나 없음 ("당신은 한국에 사는 사람입니다")
- BS: 셔플 페르소나
- A: 정상 페르소나 (재현)

**판정**:
- BS ≈ A ≈ 0% → 페르소나 내용은 무관. 모델 prior + 디코딩의 문제.
  논문 제목의 "페르소나가 입력된" 프레이밍이 틀림 → **비판 2 지지**
- BS에서 소수자 출현, A에서만 0% → 페르소나 내용이 실제로 억제 → **비판 2 기각 (논문 지지)**
- B0 vs BS 비교로 "페르소나 틀 자체"의 효과도 분리 가능

## 4. 모듈 3 — 주입 용량-반응 (비판 3: "넣어도 지워진다")

**방법**: Q3(성적지향)·Q2(장애)·Q1(출생국가)·Q4(성별정체성) 각각에 대해
소수자 정보를 3단계 강도로 주입:
- C1 (명시): 구조화 필드에 직접 추가. 예: "- 성적 지향: 동성애자"
- C2 (은근): 서술형 한 줄로 암시. 예: "- 동거인: 동성 파트너와 10년째 동거 중"
- C0 (없음): 주입 없음 (조건 A와 동일)

**판정**:
- C1에서도 0% → "넣어도 지워진다" 지지. 디코딩 단계의 문제 확정.
- C1은 유지되고 C2만 지워짐 → 문제는 스키마가 아니라 **표현 방식**.
  처방 가능: 스키마에 명시 필드로 넣으면 해결 → **비판 3 지지 + 처방 도출**
- C1/C2 모두 유지 → 소수자 주입은 작동함. 논문의 외삽 반박.

## 5. 모듈 4 — 문구 민감도 (비판 1b)

50명에 3종 문구:
- P1: 논문 원문형 (보기 번호 선택)
- P2: 역문구 ("소수자에 해당하면 해당 번호를 고르세요. 다수집단에 해당하면...")
  → 순서/프레이밍 효과 측정 (순서 편향은 LLM의 잘 알려진 아티팩트)
- P3: 개방형 ("자유롭게 한 단어로 답하세요")

## 6. 실행 순서 (빠른 판정 우선)

1. **모듈 1 (로그확률) 먼저** — 400 calls, 약 40분. 비판 1 즉시 판정.
   P(소수자)가 진짜 0이면 모듈 2·3의 해석이 달라짐.
2. 모듈 2 (셔플) — 400 calls. 비판 2 판정.
3. 모듈 3 (주입) — 800 calls. 비판 3 판정 + 처방 도출.
4. 모듈 4 (문구) — 600 calls. 부가.

## 7. 설계 A vs B 비교

| | 설계 A | 설계 B |
|---|---|---|
| 비판 1 (온도) | T=0.8 3회 샘플링 (600 calls, 간접) | 로그확률 1패스 (400 calls, 직접) |
| 비판 2 (통제) | 무페르소나만 | 무페르소나 + **셔플 통제** (인과 분리) |
| 비판 3 (외삽) | 명시 주입 단일 | **명시/은근/없음 3단계** (용량-반응) |
| 문구 민감도 | 거부옵션/개방형 2종 | 원문/역문구/개방형 3종 |
| 총 calls | ~2,200 | ~2,600 (모듈별 중단 가능) |

## 8. 정직한 한계 (A·B 공통)
- 1.5B 소형 모델: 70B와 효과 크기는 다를 수 있음. 방향성·메커니즘 검증용.
- API 키(Gemini 무료 티어 등)를 제공해주시면 동일 설계를 frontier 모델로 실행 가능.
- 한국어 단일 언어. 논문의 미국/영어 보충실험은 미포함.
